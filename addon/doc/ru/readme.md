# NVDA Dev & Test Toolbox

* Автор: Cyrille Bougot
* Совместимость с NVDA: 2019.2 и выше

NVDA Dev & Test Toolbox предоставляет инструменты для отладки и тестирования NVDA.
Инструменты для работы с журналами упрощают навигацию и анализ журналов, проверку ошибок и отслеживаний, сохранение резервных копий журналов и анонимизацию журналов перед их отправкой.
В журнал также могут быть внесены записи о конкретных вызовах функций и маркерах.
Также можно открыть соответствующий исходный код из элементов журнала, переменных консоли или даже с помощью ввода жеста команды.
Дополнение также расширяет возможности консоли Python и предоставляет такие утилиты, как обратный перевод строк интерфейса NVDA и улучшенный диалог перезапуска.

## Возможности

* Расширенный диалог перезапуска для указания некоторых дополнительных параметров при перезапуске NVDA.
* Различные функции, связанные с зарегистрированными ошибками.
* Обозреватель свойств объекта.
* Инструменты для работы со скриптами и исходным кодом: расширенный режим описания скриптов и команды для открытия исходного кода.
* Команды, помогающие считывать и анализировать журнал.
* Резервные копии старых журналов
* Команда для анонимизации журнала
* Улучшения консоли Python, такие как пользовательский скрипт запуска и возможность сохранения истории ввода в памяти после перезапуска NVDA.
* В рабочей области консоли Python есть функция для открытия исходного кода объекта.
* Команда для регистрации вызовов определённой функции (например, speech.speech.speak), включая трассировку стека.
* Команда обратного перевода элементов интерфейса.

## Команды

Это дополнение использует многослойные команды для всех новых команд, которые оно добавляет.
Точка входа для этих команд - `NVDA+Z`; таким образом, все команды должны выполняться с помощью `NVDA+Z`, за которой следует одна буква или жест.
При необходимости вы можете изменить её в диалоге жестов ввода.

В дальнейшем в этой документации мы будем обозначать этот жест как `NDTTGesture`.
Например, `NDTTGesture, S` означает `NVDA+Z, S`, если вы не изменили жест по умолчанию.

Чтобы просмотреть список всех доступных команд многоуровневого режима, нажмите `NDTTGesture, H`.

Для часто использующихся команд, вы также можете определить прямой жест в диалоге жестов ввода.

## Расширенный диалог перезапуска

Команда `NDTTGesture, Q` открывает диалог для указания дополнительных параметров перед перезапуском NVDA.
Параметры, которые можно указать, соответствуют параметрам [командной строки][2], которые можно использовать с `nvda.exe`, например, `-c` для пути конфигурации, `--disable-addons` для отключения дополнений и т. Д.

## Функции, связанные с зарегистрированными ошибками

### Сообщить о последней зарегистрированной ошибке

Нажатие `NDTTGesture, E` позволяет сообщать о последней зарегистрированной ошибке, без необходимости открывать журнал.
Повторное нажатие сбрасывает запомненную последнюю ошибку.

### Воспроизведение звука при обнаружении зарегистрированных ошибок

Параметр ["Воспроизводить звук при зарегистрированных ошибках"][4] был введён в NVDA 2021.3 и позволяет указать, будет ли NVDA воспроизводить звук ошибки в случае регистрации ошибки.

Это дополнение предоставляет дополнительную команду (`NDTTGesture, shift+E`) для переключения этой настройки.
Вы можете выбрать:

* "Только в тестовых версиях" (по умолчанию), чтобы ошибка воспроизведения NVDA воспроизводилась только в том случае, если текущая версия NVDA является тестовой (альфа, бета или запущена из исходного кода).
* "Да", чтобы включить звуковые сигналы об ошибках, независимо от вашей текущей версии NVDA.
* "Нет", чтобы отключить звуковые сигналы об ошибках независимо от текущей версии NVDA; эта функция доступна только в последних версиях NVDA.

Для NVDA до 2021.3 это дополнение обеспечивает перенос этой функции и возможность управлять ею с помощью команд с клавиатуры.
Однако, комбинированный список в панели расширенных настроек не был перенесён в более ранние версии.
Возможность отключения звуков ошибок для любой версии NVDA не была перенесена в более ранние версии, начиная с 2026.2.

## Обозреватель свойств объекта

Эта функция позволяет сообщать о некоторых свойствах текущего объекта навигатора, не открывая просмотрщик журнала.

Чтобы просмотреть свойства объекта, переместите к нему объект навигатора и используйте следующие команды:

* `NDTTGesture, стрелка вверх`: Выбирает предыдущее свойство и сообщает его в объекте навигатора.
* `NDTTGesture, стрелка вниз`: Выбирает следующее свойство и сообщает его в объекте навигатора.
* `NDTTGesture, N`: Сообщает выбранное в настоящее время свойство в объекте навигатора
* `NDTTGesture, shift+N`: Отображает выбранное в настоящее время свойство объекта навигатора в просмотровом сообщении

Список поддерживаемых свойств следующий:
имя, роль, состояние, значение, windowClassName, windowControlID, windowHandle, location, класс Python, класс Python mro.

При использовании команд навигации объекта вы также можете выбирать в настоящее время выбранное свойство вместо обычной отчётности по объектам NVDA.
Команда переключения, `NDTTGesture, control+N`, позволяет переключаться между этой пользовательской отчётностью об объектах и обычной отчетностью NVDA.

Например, вы можете выбрать свойство "windowClassName" и включить создание объявлений по настраиваемым объектам.
Тогда при перемещении объекта навигатора к следующему или предыдущему объекту вместо обычного сообщения вы услышите имя класса окна объекта.

## Инструменты для работы со скриптами и исходным кодом

<a id="sourceCodeOpeningCommands"></a>
### Команды для открытия исходного кода

Дополнение предоставляет три команды, позволяющие открыть исходный код.

Первая команда позволяет открыть исходный код скрипта, зная его жест.
Для её использования нажмите `NDTTGesture, C`, а затем выберите жест скрипта, код которого вы хотите просмотреть.
Например, чтобы увидеть код скрипта, который сообщает заголовок активного окна, нажмите `NDTTGesture, C`, а затем `NVDA+T`.

Две другие команды позволяют открыть исходный код из указанного пути:

* `NDTTGesture, shift+C`, открывает исходный код, путь к которому находится под системной кареткой.
* `NDTTGesture, control+C`, открывает исходный код, путь к которому находится под просмотровым курсором .

E.g. if the caret or the review cursor is located on the following line, the command will open the corresponding file in your editor:
`C:\Users\username\AppData\Roaming\nvda\addons\addonName\globalPlugins\addonName\__init__.py:48`

Для использования этих команд необходимо настроить [команду любимого редактора](#settingsOpenCommand) в настройках дополнения.
Если вы запускаете NVDA не из исходного кода, то путь к исходному коду NVDA (#settingsNvdaSourcePath) всё равно должен быть настроен.

### Расширенный режим описания скрипта

Режим расширенного описания скрипта позволяет сообщать информацию о скриптах без описания в режиме справки по вводу.

Когда активен режим расширенного описания скрипта, режим справки по вводу (NVDA+1) изменяется следующим образом.
Если скрипт не имеет описания, сообщаются имя и класс скрипта.
Если скрипт имеет описание, его описание сообщается как обычно.
Жест для активации или деактивации этой функции - `NDTTGesture, D`.

Выполнение жеста, привязанного к скрипту без описания в режиме справки по вводу, также создаёт запись для этого скрипта в диалоге управления жестами.
Эта запись находится в специальной категории "Скрипты без описания (изменяйте на свой страх и риск!)".
Это позволяет легко добавлять, удалять или изменять собственные жесты NVDA для этих скриптов.
Однако имейте в виду, что часто предполагается, что такой скрипт не содержит никакого описания, чтобы пользователь не мог изменить связанный жест.
Действительно, жест может быть определён в соответствии с клавишей быстрого доступа приложения.
Например, скрипт script_toggleItalic в NVDAObjects.window.winword.WordDocument привязан к control+I, и его не следует изменять, поскольку жест передаётся приложению для фактического выполнения сочетания клавиш.

#### Пример использования

Control+shift+I также переключает курсив в Word, даже если NVDA не сообщает об этом изначально.
Чтобы NVDA сообщала о результате control+shift+I как control+I, вам необходимо выполнить следующие шаги:

* Откройте документ Word.
* Включите режим расширенного описания скрипта с помощью `NDTTGesture, D`.
* Войдите в режим справки по вводу с помощью NVDA+1.
* Нажмите Control+I, чтобы сообщить о курсиве и добавить его в диалог жестов ввода.
* Выйдите из режима справки по вводу с помощью NVDA+1.
* Откройте диалог жестов ввода.
* В категории "Скрипты без описания (изменяйте на свой страх и риск!)" выберите команду "toggleItalic в NVDAObjects.window.winword.WordDocument".
* Добавьте сочетание клавиш control+shift+I и подтвердите.
* Если хотите, выйдите из режима расширенного описания скрипта с помощью `NDTTGesture, D`.

Известная ошибка: скрипт, добавленный для определённого класса, виден, даже если диалог жестов ввода открыт в другом контексте.

## Функции чтения и анализа журналов

<a id="logPlaceMarkers"></a>
### Размещайте маркеры в журнале

Во время тестирования или работы вы можете отметить определённый момент в журнале, чтобы вы могли легко обратиться к нему позже при чтении журнала.
Чтобы добавить маркерное сообщение в журнал, нажмите `NDTTGesture, K`.
A message as follows will be logged at INFO level:
`-- NDTT marker 0 --`

Вы можете добавлять в журнал столько маркеров, сколько захотите.
Номер маркера будет увеличиваться каждый раз, когда вы помещаете его в журнал; он будет сброшен только при перезапуске NVDA.

### Режим чтения журналов

Режим чтения журнала предоставляет команды для облегчения чтения журнала и анализа.
В окне просмотрщика журналов и в области вывода консоли Python функция чтения журналов включена по умолчанию, поэтому команды чтения журналов доступны немедленно.
В другой области считывания текста, такой как редактор (например, Notepad ++) или веб -страница (например, проблема Github), вам необходимо нажать `NDTTGesture, L`, чтобы включить режим чтения журнала и использовать его команды.
Когда вы закончите с чтением журнала и анализом задач, вы можете снова нажать `NDTTGesture, L`, чтобы отключить режим чтения журнала.

Команды, доступные в режиме чтения журнала, описаны ниже.
В этом режиме вы также можете нажать `control+H`, чтобы отобразить все доступные команды.

<a id="logReaderQuickNavigationCommands"></a>
#### Команды быстрой навигации

Однобуквенная команда, аналогичная клавишам быстрой навигации в режиме обзора, позволяет переходить к различным типам сообщений журнала:

* m: любое сообщение
* e: сообщения об ошибках (`ERROR` и `CRITICAL`)
* w: предупреждающие сообщения (`WARNING`)
* f: информационные сообщения (`INFO`)
* k: маркеры, ранее [помещенные в журнал](#logPlaceMarkers)
* g: предупреждающие сообщения об отладке (`DEBUGWARNING`)
* i: сообщения ввода/вывода (`IO`)
* n: сообщения ввода
* s: речевые сообщения
* b: брайлевские сообщения
* d: сообщения отладки (`DEBUG`)

Нажатие одиночной буквы приводит к переходу к следующему появлению этого сообщения.
Сочетание буквы с клавишей shift приводит к переходу к предыдущему появлению этого сообщения.

Кроме того, внутри некоторых типов сообщений можно переходить от блока к блоку, нажимая клавишу `O` или `shift+O`.
Поддерживаются следующие типы сообщений и связанные с ними блоки:

* В сообщениях, содержащих трассировку стека, например, в сообщениях об ошибках, блочная навигация позволяет переходить между трассировками стека
  Это особенно полезно, когда присутствует более одной трассировки стека, например, когда ошибка возникает в части "except" блока try/except.
* В сообщении, отображающем стеки потоков Python, регистрируемых при зависании, блочная навигация позволяет переключаться между стеками потоков.
* В сообщении, содержащем информацию для разработчиков об объекте навигатора и регистрируемом при нажатии `NVDA+F1`, блочная навигация позволяет переключаться между группами свойств.
  Существует четыре группы свойств: общие свойства, свойства модуля приложения, свойства окна и свойства, специфичные для интерфейса (IAccessible, UIA).

Наконец, внутри блока может возникнуть необходимость быстро перейти к первой или последней интересующей вас строке этого блока.
Используйте `shift+L`, чтобы перейти к первой интересующей вас строке содержимого текущего блока, например, к первому кадру трассировки стека.
А клавиша `L` используется для перехода к последней интересующей строке содержимого блока, например, к последнему кадру стека потоков или к ошибке ниже трассировки стека.

#### Перевод речевого сообщения

Иногда вам может потребоваться просмотреть журнал, созданный в системе на иностранном языке, который вы не понимаете.
Например, журнал был создан в китайской системе / NVDA, в то время как вы понимаете только французский.
Если у вас установлено дополнение [Instant Translate][3], вы можете использовать его в сочетании с [командами быстрой навигации по журналу](#logReaderQuickNavigationCommands) для перевода речевых сообщений.

* Сначала настройте языки Instant Translate.
  Исходным языком должен быть язык системы, в которой был создан журнал (например, китайский).
  Целевым языком должен быть ваш язык (например, французский).
* Откройте журнал
* Нажмите `control+T`, чтобы включить автоматический перевод речи в журнале
* Используйте команды быстрой навигации в журнале, например, S, I и т.д. При появлении речевого сообщения оно будет передано на вашем языке (в нашем предыдущем примере - на французском)

Если вы хотите отключить перевод речи, снова нажмите `control+T`.

<a id="logReaderOpenSourceFile"></a>
#### Открыть файл с исходным кодом в вашем редакторе

В журнале какая-то строка может ссылаться на исходный код:

* A line belonging to a traceback contains the path and the line in a file, e.g.:
  `  File "virtualBuffers\__init__.pyc", line 226, in _getStoryLength`
* The header line of a logged message contains the function which has logged this message, e.g.:
  `INFO - config.ConfigManager._loadConfig (22:45:26.145) - MainThread (16580):`
* The content of a message logged in input help mode (logged at info level):
  `Input help: gesture kb(desktop):NVDA+t, bound to script title on globalCommands.GlobalCommands`

Возможно, вы захотите открыть файл, содержащий этот код, чтобы понять контекст обратной трассировки или зарегистрированного сообщения.
Просто нажмите C, чтобы открыть этот файл.

Для использования этой функции необходимо настроить [команду любимого редактора](#settingsOpenCommand) в параметрах дополнения.
Если вы запускаете NVDA не из исходного кода, то путь к исходному коду NVDA (#settingsNvdaSourcePath) всё равно должен быть настроен.

#### Анализ трассировки

Sometimes you may have error tracebacks in the log, as in the following example:

    ERROR - scriptHandler.executeScript (14:47:43.426) - MainThread (15492):
error executing script: <bound method LogContainer.script_openSourceFile of <NVDAObjects.Dynamic_LogViewerLogContainerIAccessibleRichEdit50WindowNVDAObject object at 0x34C1E510>> with gesture 'c'
    Traceback (most recent call last):
      File "scriptHandler.pyc", line 300, in executeScript
      File "C:\Users\myUserName\AppData\Roaming\nvda\addons\nvdaDevTestToolbox\globalPlugins\ndtt\logReader.py", line 603, in script_openSourceFile
        if self.openStackTraceLine(line):
           ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
      File "C:\Users\myUserName\AppData\Roaming\nvda\addons\nvdaDevTestToolbox\globalPlugins\ndtt\logReader.py", line 667, in openStackTraceLine
        0 / 0  # Ошибочная строка кода
        ~~^~~
    ZeroDivisionError: деление на ноль

В тех кадрах, для которых доступен исходный код, вы могли заметить маркеры с символами `^` (крышка) и `~` (тильда).
Таким образом Python визуально указывает местоположение ошибки, а также её контекст в окне трассировки стека.
Нажатие комбинации клавиш `control+E` перемещает курсор в начало строки исходного кода, содержащей ошибку, то есть в текст, отмеченный символом `^` (крышка).
Двойное нажатие выделит этот текст.
Тройное нажатие выделяет ошибку вместе с её контекстом, то есть текстом строки исходного кода, отмеченной символами `^` (крышка) и `~` (тильда).

Обратите внимание, что для журналов, созданных с помощью NVDA версии до 2024.1, то есть с использованием Python 3.7 или более старых версий, Python указывает на ошибку только одним символом `^` (крышка).
Таким образом, двойное или тройное нажатие этой команды становится практически бесполезным.

#### Получение сводки доступных команд

Чтобы отобразить список всех доступных команд в режиме чтения журнала, нажмите `control+H`.

## Анонимизирование журнала

При сообщении о проблемах вам может потребоваться предоставить журнал событий.
Однако журналы могут содержать конфиденциальную информацию (имена пользователей, адреса электронной почты и т. д.).
Это дополнение предоставляет команду для анонимизации содержимого журнала.

Выделите часть журнала или всё его содержимое и нажмите `NDTTGesture, A`.
Анонимизированное содержимое журнала будет помещено в буфер обмена.
Вы можете вставить его в текущее выделение, чтобы заменить его, или в любое другое место по вашему желанию.

Для использования этой функции необходимо настроить правила анонимизации, используемые данной командой.
Файл для настройки этих правил находится по пути: `pathToNVDAConfig\ndtt\anonymizationRules.dic` (напр., `C:\Users\myUserName\AppData\Roaming\nvda\ndtt\anonymizationRules.dic`).
Все инструкции по записи этого файла вы найдёте в его заголовке.
Если вы повредили файл правил анонимизации или удалили инструкции заголовка, просто удалите или переименуйте этот файл, и новая версия этого файла будет сгенерирована при следующем запуске.

<a id="oldLogsBackup"></a>
## Резервное копирование старых журналов

NVDA уже предоставляет резервную копию журнала предыдущей сессии NVDA; файл называется "nvda-old.log`.
Однако иногда вам может потребоваться получить доступ к более старым журналам, например, из-за того, что вам пришлось снова перезапустить NVDA, прежде чем просматривать `nvda-old.log`.
Это дополнение позволяет вам настроить, хотите ли вы создавать резервные копии старых журналов и сколько их; это делается в [настройках дополнения](#settingsLogsBackup).

Диалог диспетчера журнала позволяет просматривать резервные журналы.
Его можно открыть, перейдя в меню NVDA -> Инструменты -> Диспетчер журналов
В этом диалоге вы можете видеть список всех журналов резервного копирования и выполнять различные действия в выбранном журнале:

* для его открытия (нажмите `Enter`)
* для его удаления (нажмите `Delete`)
* копировать файл журнала (нажмите `control+C`)

Вы также можете выбрать несколько журналов для выполнения действий по всем им.

Чтобы иметь возможность открыть журнал, вы должны сначала настроить [команду для открытия файла в вашем любимом редакторе](#settingsOpenCommand).

## Расширение консоли Python

<a id="pythonConsoleOpenCodeFile"></a>
### функция `openCodeFile`

In the console, you can call the following function to view the source code that defines the variable `myVar`:
`openCodeFile(myVar)`

Для работы этой функции необходимо настроить [команду любимого редактора](#settingsOpenCommand) в параметрах дополнения.
Если вы запускаете NVDA не из исходного кода, то путь к исходному коду NVDA (#settingsNvdaSourcePath) всё равно должен быть настроен.

Функции `openCodeFile` могут быть вызваны для объектов, определённых в коде NVDA, или для объектов, определённых дополнениями.
Они не могут быть вызваны для объектов, исходный код которых недоступен, таких как встроенные модули python.

Если вы ещё не импортировали объект в консоль, вы также можете передать его имя в качестве параметра функции `openCodeFile`.

Ниже приведены примеры вызовов в коде NVDA:

* View the definition of the function `speech.speech.speak`:
  `openCodeFile(speech.speech.speak)`
  or with the name passed as parameter:
  `openCodeFile("speech.speech.speak")`
* View the definition of the class `TextInfo`:
  `openCodeFile(textInfos.TextInfo)`
* View the definition of the method `copyToClipboard` of the class `TextInfo`:
  `openCodeFile(textInfos.TextInfo.copyToClipboard)`
* View the definition of the class of the focused object:
  `openCodeFile(focus)`
* Open the file `api.py` defining the module `api`:
  `openCodeFile(api)`

### Скрипт при запуске консоли Python

Вы можете определить собственный скрипт, который будет выполняться в пространстве имён консоли Python при её первом открытии.

For example, the script allows you to execute new imports and define aliases that you will be able to use directly in the console, as shown below:

    # Различные импортируемые данные, которые я хочу отобразить в консоли.
    import globalVars as gv
    import core
    import ui
    # Псевдонимы
    ocf = openCodeFile

The Python console script should be placed in the following location: `pathToNVDAConfig\ndtt\consoleStartup.py`
Например: `C:\Users\myUserName\AppData\Roaming\nvda\ndtt\consoleStartup.py`

Примечание: В Python 2, то есть в NVDA 2019.2.1 или более ранних версиях, поддерживаются только тексты в формате ASCII; любые другие кодировки, такие как Unicode, не поддерживаются.

### Сохранение истории ввода в консоль Python

В истории консоли Python вы можете использовать стрелки вверх и вниз для просмотра и изменения предыдущих введённых данных.
Однако список предыдущих данных ввода очищается при выходе из NVDA.
Это дополнение предоставляет [настройку](#settingsPreserveHistory), включённую по умолчанию, которая позволяет сохранять историю ввода в консоли Python даже при перезапуске NVDA.

<a id="loggingFunctionCall"></a>
## Журналирование вызовов функций

Иногда может возникнуть необходимость узнать, какая часть кода отвечает за озвучивание того или иного текста.
Для этого можно включить журналирование вызовов функции `speech.speech.speak`, нажав `NDTTGesture, S`.
Каждый раз, когда NVDA произносит речь, в журнал записывается соответствующее сообщение, включая трассировку стека, что позволяет определить код, вызвавший этот речевой вывод.
После завершения отключите журналирование вызовов функций тем же способом.

Аналогичным образом, вы можете записывать в журнал вызовы функций вывода `tones.beep`, `braille.BrailleBuffer.update` или `nvwave.playWaveFile`, чтобы отслеживать источник звукового сигнала, вывода текста по брайлю или звука (например, звука орфографической ошибки).
[Целевую функцию](#targetFunctionForCallLogSetting) можно выбрать в параметрах дополнения.
Вы даже можете записывать в лог стек вызовов пользовательской функции.

По умолчанию журналирование вызовов функций выполняется с помощью метода "settrace": он использует `sys.settrace`, `threading.settrace` и/или `threading.settrace_all_threads` для установки функции обратного вызова трассировки, которая вызывается при возврате из целевой функции.
В качестве альтернативы, если вы не получите удовлетворительных результатов, вы можете выбрать метод "monkey patching", при котором целевая функция (например, `speech.speech.speak`) подвергается патчингу.
Оба метода имеют ограничения, которые могут препятствовать регистрации вызовов функций в определенных комбинированных условиях.
Например, метод "settrace" может не работать с версиями NVDA ниже 2026.1, если целевая функция выполняется из потока, отличного от основного, и если журналирование вызовов функции включено после запуска потока целевой функции.
С другой стороны, метод "monkey patching" может не сработать, если целевая функция импортируется через оператор "from import" (например, `from tones import beep`).

Вы можете изменить способ журналирования вызовов функций в [специальной настройке](#functionCallLogMethodSetting) или нажав `NDTTGesture, shift+S`.

<a id="reverseTranslationCommand"></a>
## Команда обратного перевода

Многие тестировщики используют NVDA на другом языке, а не на английском.
Но при объявлениях результатов теста на GitHub описание изменённых параметров или сообщений, представленных NVDA, должны быть написаны на английском.
Это довольно разочаровывает и требует много времени, чтобы перезапустить NVDA на английском языке для проверки точной формулировки вариантов или сообщений.

Чтобы этого избежать, дополнение предоставляет две команды обратного перевода, позволяющие переводить интерфейс NVDA, например, сообщения, метки элементов управления в графическом интерфейсе и т. д.

* `NDTTGesture, R` использует функцию перевода gettext из NVDA для попытки обратного перевода последнего высказывания.
* `NDTTGesture, shift+R` использует функции перевода текста из NVDA и её дополнений для попытки обратного перевода последней произнесённой фразы.

Более конкретно, первая строка последней речевой последовательности переводится в обратном порядке.

Например, во французской версии NVDA, если я стрелкой вниз выберу меню "Инструменты" с названием "Outils", NVDA отобразит "Outils sous-Menu o", что означает "Инструменты подменю o".
Если я сразу после этого нажму команду обратного перевода, NVDA будет отменять перевод "Outils" в "Инструменты".

Просматривая журнал после этого, мы можем найти следующие строки:

    IO - speech.speech.speak (23:38:24.450) - MainThread (2044):
    Speaking ['Outils', 'sous-Menu', CharacterModeCommand(True), 'o', CharacterModeCommand(False), CancellableSpeech (still valid)]

Это подтверждает, что "Outils" была первой строкой в ​​последовательности речи.

В случае, если обратный перевод приводит к двум или более возможным результатам, контекстное меню открывается в перечислении всех возможностей.

Результат обратного перевода также копируется в буфер обмена, если включён соответствующий [параметр](#settingsCopyReverseTranslation), что является значением по умолчанию.

Обратный перевод строк NVDA доступен только для версии NVDA 2022.1 и выше.
В более ранних версиях NVDA для обратного перевода доступны только строки дополнений.

Кроме того, в версии NVDA 2019.2.1 и более ранних версиях, если обратный перевод не найден, предпринимается вторая попытка в первой части строки.
Действительно, в этих версиях NVDA речевая последовательность выглядит следующим образом:

    IO - speech.speak (12:39:12.684):
    Speaking [u'Outils  sous-Menu  o']

Мы видим, что метка объекта может быть объединена с ролью, состоянием, горячей клавишей и т. д.
Таким образом, если обратный перевод не даёт результата для всей строки, предпринимается вторая попытка для части строки перед двойным пробелом ("  ").
Однако это не является абсолютно надёжным доказательством, поскольку мы не можем исключить, что строка на самом деле содержит двойной пробел.

<a id="settings"></a>
## Настройки

Для работы некоторых функций дополнения может потребоваться определённая настройка.
Панель настроек позволяет включать их или управлять их работой.
Чтобы просмотреть и изменить эти настройки, перейдите в меню NVDA -> Настройки и выберите категорию NVDA Dev & Test Toolbox.
Доступ к этому диалогу настроек также можно получить непосредственно из диалога диспетчера журналов.

Эти параметры являются глобальными и могут быть настроены только в том случае, если активен профиль по умолчанию.

<a id="settingsOpenCommand"></a>
### Команда для открытия файла в вашем любимом редакторе

Некоторые функции позволяют просматривать содержимое в вашем любимом редакторе.
Сюда входят команды для просмотра исходного файла [из журнала](#logReaderOpenSourceFile), [из объекта в консоли](#pythonConsoleOpenCodeFile) или [для введённого жеста](#scriptOpener), а также кнопка открытия [диспетчера журналов](#oldLogsBackup).

Чтобы их использовать, сначала необходимо настроить команду, которая будет вызываться для открытия файла в вашем любимом редакторе.
The command should be of the form:
`"C:\path\to\my\editor\editor.exe" "{path}":{line}`
Разумеется, вам следует изменить эту строку в соответствии с реальным именем и местоположением вашего редактора, а также синтаксисом, используемым им для открытия файлов.
`{path}` будет заменён полным путём к файлу, который нужно открыть и `{line}` - номером строки, на которую вы хотите установить курсор.
For Notepad++ for example the command to type in the console would be:
`"C:\Program Files\Notepad++\notepad++.exe" "{path}" -n{line}`

<a id="settingsNvdaSourcePath"></a>
### Путь к исходному коду NVDA

При использовании команды для [просмотра исходного файла из журнала](#logReaderOpenSourceFile), [из объекта в консоли](#pythonConsoleOpenCodeFile) или [для введённого жеста](#scriptOpener)файл может принадлежать самой NVDA.
Если вы не используете NVDA из исходного кода, ваша NVDA содержит только скомпилированные файлы.
Таким образом, вы можете указать здесь альтернативное местоположение, где будет найден соответствующий исходный файл, например, место, где вы клонировали исходные файлы NVDA, чтобы исходный файл всё равно можно было открыть.
The path should be such as:
`C:\pathExample\GIT\nvda\source`
Конечно, замените путь к исходному коду NVDA на правильный.

Однако убедитесь, что версия вашего исходного файла (например, фиксации GIT) совпадает с версией работающего экземпляра NVDA.

<a id="settingsLogsBackup"></a>
### Резервное копирование старых журналов

Комбинированный список резервного копирования старых журналов позволяет включить или отключить эту [функцию](#oldLogsBackup).
Если эта функция включена, вы также можете указать ниже в разделе "ограничения количество резервных копий" максимальное количество резервных копий, которые вы хотите сохранить.
Эти настройки вступят в силу только при следующем запуске NVDA, когда будет выполнено резервное копирование.

<a id="settingsCopyReverseTranslation"></a>
### Копировать обратный перевод в буфер обмена

Этот параметр позволяет выбирать, будет ли [команда обратного перевода](#reverseTranslationCommand) копировать свой результат в буфер обмена.

<a id="settingsPreserveHistory"></a>
### Сохранение истории ввода в консоли после перезапуска

Если этот флажок установлен, история ввода в консоли Python будет сохраняться после перезапуска NVDA.
Если этот параметр отмечен, вы также можете указать ниже максимальное количество сохраняемых данных.
Если этот параметр не отмечен, NVDA будет работать как обычно, то есть после перезапуска история консоли будет пустой.

<a id="targetFunctionForCallLogSetting"></a>
### Целевая функция для журналирования вызовов функций

Этот комбинированный список определяет функцию, вызовы которой будут регистрироваться при включении [журналирования вызовов функций](#loggingFunctionCall).
Вы можете выбрать функцию из множества доступных вариантов вывода или выбрать пользовательский вариант.

Если вы выберете вариант с пользовательской функцией, вам потребуется ввести полное имя функции, для которой вы хотите журналировать вызовы.
Полное название должно включать в себя его местоположение (пакет, модуль, класс и т. д.).
Будьте внимательны при определении функции, указывая её исходное местоположение, то есть место, где она была фактически определена, иначе журналирование вызовов будет работать с меньшей вероятностью.
Например, используйте `speech.speech.getCurrentLanguage`, которая обращается к функции, определённой в `speech\speech.py`, а не к `speech.getCurrentLanguage`, которая обращается к символу, импортированному в `speech\__init__.py`.

<a id="functionCallLogMethodSetting"></a>
### Метод журналирования вызовов функций

Этот комбинированный список определяет метод, используемый для идентификации вызовов функций, когда включена функция [журналирования вызовов функций](#loggingFunctionCall).
Этот параметр также можно переключать, нажав `NDTTGesture, shift+S`.
При изменении этого метода он будет применяться в первую очередь при следующей активации журналирования вызовов функций; то есть, он не будет применяться к текущему журналу вызовов функций, если он в данный момент включен.
